01 — The mechanism

Three layers: raw → silver → gold

A medallion architecture. Bronze/raw lands the CSV as-is; Silver/staging cleans, types & classifies it (and does the valid-vs-quarantine split); Gold/marts is the business-ready star. Airflow orchestrates; dbt transforms, rendered by Cosmos so each model is its own Airflow task.

02 — Data quality

What happens to each row

The source is deliberately dirty. Every row is recovered, flagged, or quarantined — this table shows exactly which, and why.

Example from the CSVThe problemWhat the pipeline doesResult
customer_id = 501.0 stored as a float cast to integer → 501 Fact
18-07-2023 date in DD-MM-YYYY, not ISO parse → 2023-07-18 Fact
T1010 · P100 IDs carry a stray prefix strip prefix → 1010 · 100 Fact
customer_id = (empty) a dimension key is missing keep row, map to unknown (-1), set missing_customer Fact · flagged
price = "Two Hundred" not a number → the amount can't be computed reject with reason price_not_numeric Quarantine
The rule in one line: recover formatting where safe · quarantine when the amount can't be computed (bad price / tax / quantity) · flag (don't drop) a usable row missing a dimension like the customer. And it reconciles: 71 modelled + 29 quarantined = 100.
flagged stays in Gold

Kept in fct_transactions, attributed to the unknown customer (-1) with missing_customer = true. It still counts in revenue — in agg_sales_by_customer it shows as is_unknown, so analysts include or exclude it on purpose. Nothing hidden, nothing lost.

quarantined segregated & remediated

Split off in Silver to quarantine_customer_transactions with its dq_reasons. Surfaced by dq_completeness / dq_run_audit and alerted past a threshold. Remediation loop: fix the source → re-run (idempotent) reprocesses it back into the model.

03 — Architecture Decision Records

Five decisions, pros & cons

Every significant choice is captured as an ADR — context, options, decision, consequences. Summarized here with the trade-offs; full records in docs/adr/.

ADR 0001

Cosmos for dbt-in-Airflow

Render dbt with Astronomer Cosmos — each model becomes its own Airflow task; dbt runs from an isolated venv. Rejected: BashOperator, DockerOperator, dbt Cloud, K8s pods.

Pros
  • Per-model retries & lineage in the UI
  • dbt env isolated from Airflow's
  • Community standard; scales unchanged
Cons
  • Extra dependency & config surface
  • Installs deps at render
  • Arguably overkill for a few models
ADR 0002

Config & secrets

Inline ${VAR:-default} for local dev; source secrets from a manager for real deployments.

Pros
  • Zero-setup docker compose up
  • No secrets committed to the repo
  • Clear seam to a secrets manager
Cons
  • Default creds in committed YAML
  • Local throwaway only — not deployable
ADR 0003

Classic dbt engine

Pin classic dbt-core 1.9, not the dbt 2.0 "Fusion" pre-release (which dropped the Postgres adapter).

Pros
  • Postgres fully supported
  • Reproducible, deterministic builds
  • Mature, stable engine
Cons
  • Not on the newer Rust engine
  • Revisit when Fusion supports Postgres
ADR 0004

Bake code into the image

COPY dags/dbt into the image; compose bind-mounts override those paths for fast local dev.

Pros
  • Immutable, shippable artifact (git SHA)
  • Dev speed unchanged — mount wins
  • Git = source of truth, image = runtime
Cons
  • Two delivery paths to keep in mind
  • Rebuild to ship code changes
ADR 0005

Data-quality strategy

Coerce · quarantine · flag. Recover safe formatting; quarantine broken measures with reasons; flag (don't drop) missing dimensions. No word→number; tax is absolute.

Pros
  • Nothing dropped silently (reconciles to 100)
  • Explicit, testable, auditable rules
  • Revenue not distorted by invented values
Cons
  • Rules are dataset-specific
  • Quarantines 16 missing-quantity rows

06 — For the call

Six things worth saying out loud

1
"I landed raw as text on purpose." ELT — dirty data survives ingest; dbt owns cleaning.
2
"Nothing is dropped silently." Coerce / quarantine / flag, with reasons, reconciled to 100.
3
"dbt is decoupled from Airflow." Isolated venv + Cosmos per-model tasks.
4
"tax is absolute — and I proved it." Correlation ≈ 0, not a guess.
5
"Contracts + schemas + tests." A stable interface — governance, not just transformation.
6
"I know what I kept simple" — and the exact upgrade path for each.
One story to tell: during clean-room verification I found Cosmos running dbt deps per task (~40×) — a run took 5 minutes. LOCAL execution runs in the project dir where packages are already baked, so I removed the per-task install: the pipeline dropped to 36 seconds. That's the platform mindset — measure, find the waste, fix it.
