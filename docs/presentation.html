01 — The mechanism

One DAG: ingest, then transform

Airflow orchestrates the flow; dbt does the transformation, rendered by Cosmos so each model is its own Airflow task. The raw CSV lands as text — nothing is rejected at ingest — then dbt cleans, splits, and models it.

The rule in one line: recover formatting where safe · quarantine when the amount can't be computed (bad price / tax / quantity) · flag (don't drop) a usable row missing a dimension like the customer. And it reconciles: 71 modelled + 29 quarantined = 100.
03 — Decisions & trade-offs

Every choice is a defensible trade-off

Recorded as ADRs. The point of each isn't the choice — it's knowing the cost and when you'd revisit it.

ELT, land as TEXT

Dirty values survive ingest; raw stays an immutable source of truth.

Trade-off: raw isn't query-ready — dbt owns cleaning.

Cosmos for dbt ADR 0001

Per-model Airflow tasks; dbt's env isolated from Airflow's.

Guards against the real failure mode: dependency conflicts.

Quarantine vs flag ADR 0005

Don't drop revenue over a missing key; don't invent monetary values.

Trade-off: 29% segregated on this (dirty) sample — visible, not hidden.

tax = absolute amount proven

Correlation with price ≈ 0, continuous values — measured, not guessed.

total = quantity × price + tax.

Model contracts + schemas

Typed, stable interface for consumers; staging vs analytics separated.

Schema changes need an explicit update — that's the point.

Classic dbt-core ADR 0003

dbt 2.0 "Fusion" dropped Postgres — pinned the classic engine.

Revisit when Fusion supports Postgres or we move to a cloud DW.

06 — For the call

Six things worth saying out loud

1
"I landed raw as text on purpose." ELT — dirty data survives ingest; dbt owns cleaning.
2
"Nothing is dropped silently." Coerce / quarantine / flag, with reasons, reconciled to 100.
3
"dbt is decoupled from Airflow." Isolated venv + Cosmos per-model tasks.
4
"tax is absolute — and I proved it." Correlation ≈ 0, not a guess.
5
"Contracts + schemas + tests." A stable interface — governance, not just transformation.
6
"I know what I kept simple" — and the exact upgrade path for each.
One story to tell: during clean-room verification I found Cosmos running dbt deps per task (~40×) — a run took 5 minutes. LOCAL execution runs in the project dir where packages are already baked, so I removed the per-task install: the pipeline dropped to 36 seconds. That's the platform mindset — measure, find the waste, fix it.
